## 運賃が実際と合わないときの切り分け

1. **運賃表が古い** … 上の一覧の確認日を見る。改定を取りこぼしていることが多い
2. **距離の推定誤差** … 駅の緯度経度から直線距離を出し `ROUTE_FACTOR`(1.04)を掛けている。
   急行線など駅間が長い区間では線路の曲がりを拾えず短めに出る
3. **経路選択の違い** … 本アプリと乗換案内サービスが別の経路を選んでいる場合がある。
   どちらも実在の経路なら運賃計算自体は正しい。`tools/test_single_route.js` で経路を突き合わせる

## 徒歩乗換について

`network.json` の徒歩乗換は `tools/build_network.py` が生成する。条件は
**別の駅どうしで直線400m以内**という機械的なもので、実際に歩かれている乗り継ぎでも
これを外れると出てこない。秋葉原(JR・日比谷線・TX)と岩本町(都営新宿線)が
直線415mでちょうど漏れていたのがその例。

閾値を上げると並行路線の隣どうし(板橋と北池袋など)まで乗り換え扱いになってしまうため、
**必要なものだけ `build_network.py` の `EXTRA_WALK` に手で書く**方針にしている。
400〜600mには他にも実用的な組(上野と京成上野、新宿と新宿西口など)が埋もれているので、
使っていて不便に気づいたらそこに足す。

## 事業者をまたぐ乗継割引

運賃を事業者ごとに独立して求めて足すと、実際より高く出る組み合わせがある。
東京メトロと都営地下鉄を直接乗り継ぐ場合、両社の合算から割り引かれるため。
`fares.js` の `TRANSFER_DISCOUNT` で 70円 として実装している。

**この割引は通常運賃にだけ効く。** 都営線の無料乗車券を使う利用者はメトロ側を
単独のきっぷで買うので、連絡乗車券にはならず割引は適用されない。実費は変わらない。

### 未確認事項

舞浜→押上(JR→メトロ→都営)を乗換案内で引くと 260 + 320 = 580円 になる。
一方 180(メトロ) + 220(都営) - 70(割引) = 330 とすると、合計は590円で10円合わない。
考えられる原因:

- 連絡運賃が「単純合算 - 一律の割引額」ではない(連絡運賃表が別にある)
- どちらかの単独運賃の想定が10円ずれている
- 割引額が70円ではない

公表されている割引額は70円なのでそれを採っている。10円の差は本サービスの
「目安」の範囲内。正確を期すなら、都営交通または東京メトロの連絡運賃表で確認すること。
